# Результат интеграции oko

## Загрузка оформления после перезапуска

Статические ресурсы получают явные MIME-типы независимо от настроек Windows: в частности font/ttf для шрифта и application/javascript для модулей. Проверка кэша обязательна и для ответов 304. HTML использует общий каталог /_ui/<revision>/; относительные импорты модулей, CSS-текстуры, шрифт, фон, музыка и титры сохраняют ту же версию. При правке интерфейса меняются адреса всех зависимостей, включая вложенные файлы, которые раньше могли оставаться в старом кэше. Фон и приветствие имеют статическое отображение до запуска JavaScript.

Наблюдавшийся у пользователя вид без оформления не воспроизвёлся в чистых Chrome и Edge. Подтверждены и исправлены ошибка MIME шрифта и неполное обновление адресов вложенных ресурсов. Проверено: 58 тестов, включая выдачу зависимостей из каталога версии и защиту от выхода за статический каталог. Предыдущая проверка реального Chrome с повторной загрузкой, шрифтом, текстурами и запасным отображением без JavaScript — qa/chrome-recovery-results.json. Пользовательский профиль Chrome не доступен для прямой проверки; его проблему нельзя считать подтверждённо устранённой до проверки пользователем. Автономная страница /static/diagnostics.html собирает в этом браузере локальный отчёт о загруженных ресурсах и применённых стилях; ключи и хранилища не читаются, отчёт автоматически никуда не отправляется.

Дополнительно qa/chrome_asset_release_check.py выполнил 24 проверки в установленном Chrome 155. Во временном локальном прокси браузеру сначала выданы намеренно сломанные JS/CSS со сроком кэша в один год; повторная загрузка подтвердила использование этих старых копий без обращения к серверу. После перехода на актуальный HTML все ресурсы пришли из общего каталога версии, старые /static не запрашивались. Подтверждены весь граф модулей, Pixel-шрифт, деревянная текстура, золотой логотип и нарисованный фон; ошибок JS и загрузки нет. Проверено также статическое отображение без JS. Результат — qa/chrome-asset-release-results.json; снимки — qa/chrome-asset-release.png и qa/chrome-asset-release-no-js.png. Пользовательские ключи, видео и профиль не использовались.

## Правки интерфейса по скриншотам

На деревянной табличке размещён объёмный логотип OKO заглавными буквами с мотивом глаза. Табличка увеличена до 840–880 px на компьютере, логотип до 440–480 px; увеличены надписи, приветствие, поля и кнопка входа. Проверены экраны 320/390/1366/1920 px без перекрытий формы и горизонтального скролла; на коротких экранах доступна вертикальная прокрутка. Стрелка «Назад» возвращает из End в Nether, затем из Nether в Overworld, сохраняя текущую рабочую сцену. Между Nether и End в обе стороны восстановлен полный двухсекундный портальный переход с отдельной палитрой End; короткий выход сохранён для титров, а режим уменьшенного движения учитывается.

Прежние композиции Overworld, Nether и End сохранены. По последнему запросу восстановлен исходный вид Overworld: прежнее изображение, пиксельная сетка 640×360 и исходные цвета без фильтра насыщенности/яркости. В Nether и End мелкая фактура усредняется до 480×270; фильтры только на фоне: Nether 78%/88%, End 55%/82%. Исходные PNG и их контрольные суммы сохранены. Созданный ранее мягкий overworld-soft.png остаётся неиспользуемой альтернативой. Название интерфейса и титров — oko. Большой остров с порталом открывает титры по нажатию. В титрах нет верхней панели. Текстовые вкладки в шапке убраны; вход в End и историю — фиолетовая квадратная кнопка со стрелкой вправо на правом краю панели, новая проверка — кнопкой на странице истории.

Строка форматов и внутренних лимитов убрана из рабочей сцены; ограничения доступны в справке и сообщениях выбора файла. Ответ API всегда открыт. Поиск, списки фильтров и отметки просмотра оформлены заново с управлением с клавиатуры. Вертикальные миниатюры таймлайна ограничены по размеру и границам экрана. Исправлено горизонтальное переполнение на мобильном экране.

Видимый результат относится к фактически работавшему детектору V13. Технические детали доступны в блоке «Что проверено и как». Совместимость с уже запущенным сервером обеспечена чтением его фактических detectors; неизвестным старым отчётам охват не приписывается. Процесс на порту 8766 продолжает работать без перезапуска; новые backend-поля analysis_scope будут также доступны после обычного следующего запуска.

Проверка: 38 серверных тестов; qa/ui_refresh_check.py проверяет реальный анализ синтетического вертикального видео, постоянный JSON, отметки просмотра, поиск, фильтры с клавиатуры, портал, титры, восстановление панели и экраны 1920/390 px. Личные видео не использовались. Результаты — qa/ui-refresh-results.json; скриншоты — qa/refresh-*.png.

Изменения внесены в существующий fortebank-video-audit. Minecraft-интерфейс сохранён; анализ OKO, постоянный архив и новые сцены работают в одном приложении.

## Готовые функции

- Сервер принимает форматы OKO и отдаёт реальные capabilities. API жюри сохраняет HTTP 200 и строгую схему результата.
- Встроен локальный obstruction/V13, каталог 21 типа, склейка кандидатов, confidence/review и нормативные ссылки.
- Отчёт содержит реальные JPEG, кадры с таймкодами, интервалы, источники, миниатюры, движение и покрытие видео.
- Интерфейс соединён с расширенным API: чат эпизодов, evidence dialog, таймлайн, полный JSON, справка норм и API.
- SQLite хранит отдельные VideoAsset и AnalysisRun. Повторный намеренный анализ создаёт новый запуск; повтор одного запроса идемпотентен.
- Архив End поддерживает поиск, состояния, просмотр человеком, сортировку, страницы по три проверки, открытие и удаление.
- Видео и отчёт восстанавливаются после перезагрузки страницы и сервера без обращения к модели. Позиция и просмотренные эпизоды сохраняются отдельно от вердикта.
- «Убрать видео» очищает рабочее окно. Принятый A продолжает анализ; поздний A не заменяет выбранный B.
- Удаление учитывает общие видео, активных читателей и tombstone. Повтор сохранения использует staged-результат, а не новый анализ.
- Legacy SQLite получает согласованный backup перед изменением схемы, включая committed WAL. Старые JSON OKO импортируются без потери отчёта; утраченный оригинал честно отмечается.
- Есть три спокойных пиксельных мира, отдельный горизонтальный вход End, нижний выход, управляемые титры и четыре имени из пакета.
- Сохранены плеер 1×/2×, fullscreen, клавиатура, музыка, mute, duck, темы и ручное отключение движения. Reduced motion, скрытая вкладка и отказ storage обработаны.
- Обычный запуск start.ps1 подготавливает окружение и запускает единый локальный сервис; Docker-конфигурация использует отдельный worker.

Полная карта функций: FEATURE_MAP.md. Инструкция запуска и хранения: README.md.

## Ограничения

Действующий автоматический детектор — V13. Модель команды и веса не предоставлены; её predict остаётся точкой подключения. Остальные типы каталога нельзя представлять реализованными детекторами. Ошибка включённой внешней модели становится failed.

После уточнения интерфейса добавлены явные метаданные `analysis_scope` в capabilities, приватный каталог и каждую проверку. Сохраняется различие между локальной эвристикой видимости камеры и будущей внешней моделью. Команда запуска модели помечается непроверенной до успешного выполнения и не объявляет весь каталог доступным для распознавания. Старые отчёты используют сведения собственных детекторов или снимка настроек; отсутствие этих сведений обозначается как неизвестная область. Компактный API жюри сохранён без дополнительных полей. Его `no_violation` относится только к работавшим детекторам.

Дополнительно устранён случай, когда ошибка завершения единственного CV-детектора могла стать пустым успешным отчётом. Теперь отсутствие успешно завершившихся детекторов приводит к ошибке проверки. После изменений полный локальный pytest: **38 passed** за 17,54 с; новые проверки охватывают сохранение области прежнего отчёта после включения модели, честную неизвестную область legacy и ошибку CV-детектора. Использованы только временные базы и синтетические видео.

Архив — общий приватный архив этого развёртывания по ключу/сессии, без персональных аккаунтов и облачной синхронизации. Видео UI хранятся до удаления; свободное место и резервное копирование каталога DATA_DIR контролирует владелец сервиса.

Подключены пользовательские end.m4a (End, 8%) и titles.m4a (титры, 10%). Восемь сценариев реального воспроизведения в Edge подтвердили уровни, декодирование, затухание, паузу, mute и возврат после скрытия страницы; ошибок JavaScript и медиа нет. Данные — qa/end-titles-audio-results.json. Для портального перехода сохранены заменяемые собственные эффекты. Существующий приватный Minecraft-пакет не включён в переносимый архив.

Docker-сборка, Safari/Firefox и качество модели на банковском датасете не проверялись. Юридическая актуальность каталога заново не подтверждалась; исходные флаги verified не являются автоматической юридической проверкой.
