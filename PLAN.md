# План разработки сервиса проверки кассовых операций

## Цель

Подготовить работающую локальную основу для видеоанализа из кейса ForteBank. Коллега предоставляет обученную модель как локальную команду по согласованному контракту. Дизайн пользовательского интерфейса выполняется отдельно после готовности основы.

## Решение

Сервис состоит из веб API, очереди заданий SQLite и отдельного процесса анализа. Видеозапись остается в локальном хранилище. Процесс анализа запускается в контейнере без сети, вызывает модель, проверяет ее структурированный ответ, извлекает реальные JPEG кадры из указанных таймкодов и связывает обнаруженные признаки с каталогом проверенных нормативных правил. Модель не генерирует нормативные ссылки.

## Этапы

1. Зафиксировать контракт модели: вход — путь к файлу `.mov` и длительность; выход — список наблюдаемых событий с кодом типа, таймкодом, описанием и временем кадров. Неизвестный тип, неверный таймкод и ошибка модели переводят задание в `failed`.
2. Реализовать `POST /api/v1/analyze` и `GET /api/v1/jobs/{job_id}` с `X-API-Key`, ограничением размера, сохранением задания и устойчивой очередью. Сохранить формат ответа жюри.
3. Реализовать локальный обработчик с лимитом времени, проверкой видео через FFprobe, извлечением кадров через FFmpeg и удалением исходного видео после завершения.
4. Добавить каталог типов событий и нормативных источников Республики Казахстан с точным документом, пунктом и ссылкой. Включать только события, действительно наблюдаемые на видео; описание остается предположением для проверки человеком.
5. Добавить минимальный рабочий экран для загрузки, статуса и результатов без дизайна.
6. Настроить запуск через Docker Compose: веб сервис и обработчик; у обработчика нет сети. Добавить инструкции интеграции модели, проверки API и известные ограничения.
7. Проверить сценарии загрузки, успешной обработки, нескольких событий, отсутствия событий, сбоя модели, неверного ключа и некорректного файла.

## Готовность к объединению с моделью

Коллега кладет `infer.py` и веса в папку `model/`, реализует документированный JSON контракт и указывает команду запуска в `.env`. Сервису не требуется менять API, очередь, правила, обработку кадров или веб экран. Список кодов событий и пороги модели согласуются на данных хакатона. До подключения весов сервис сообщает об ошибке модели, а не выдает ложный результат «нарушений нет».

## Ограничения входных данных

Датасет и веса не приложены. Качество обнаружения и точность таймкодов можно измерить только после их получения. Публичный URL и TLS зависят от сервера команды; локальная сборка подготавливает порт и API ключ, но сама не публикует сервис в интернет.
